# Phase 2AK — Process-crash recovery regression tests

## Purpose

Exercise abrupt interpreter termination at carefully selected local publication boundaries. Existing exception/fault-injection tests run Python cleanup handlers; these tests use child processes terminated with `os._exit`, which bypasses Python `finally` blocks and exception handlers.

## Scenarios

| Test | Crash point | Required observation |
|---|---|---|
| AK-1 | During staged-file fsync, before final hard-link publication | Final destination is absent; a hidden staging file may remain with complete staged bytes |
| AK-2 | After backup publication, before checkpoint publication | Backup exists, checkpoint is absent, and verification fails closed |
| AK-3 | During restore staging fsync, before final publication | Restore destination is absent; staging residue may remain; source backup and checkpoint hashes are unchanged and still verify |

## Safety controls

- Every scenario uses a child Python interpreter and a unique `TemporaryDirectory`.
- Audit records are synthetic and generated by the existing local audit helper.
- The only forced process exit is inside the child interpreter.
- No host process is killed, no device power is interrupted, no storage is filled, no client evidence is opened, and no network or target assessment is performed.
- Temporary staging residue is confined to the temporary directory and is removed when the test fixture is cleaned up.
- Each child has a 15-second timeout.

## Run

From the repository root:

```bash
python3 -m compileall -q apex_storage.py apex_audit.py apex_audit_backup.py tests
python3 -m unittest discover -s tests -p 'test_storage_crash_recovery.py' -v
python3 -m unittest discover -s tests -v
```

The focused suite must report three executed tests. A skipped or unmatched test file is not a pass.

## Interpretation limits

These tests prove only the observed process-exit behavior on the filesystem hosting the test's temporary directory. They do not simulate kernel panic, power loss, storage-controller cache loss, filesystem journal replay, removable-storage semantics, or VM crash consistency. A real power-loss drill remains restricted to a disposable VM or dedicated lab device under the Phase 2AI runbook.

## Exit gate

Phase 2AK is complete when the focused tests and full CI matrix pass, and the user confirms the focused and full suites on the intended Termux environment. Physical filesystem and power-loss drills remain separately outstanding.
